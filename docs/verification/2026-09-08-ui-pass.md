# Promptbox UI and optimization pass

Verified on 2026-09-08 against the local production build at
`http://127.0.0.1:4322/promptbox/`. The measurements below cover the initial UI pass,
before the subsequent onboarding content updates.

## Changes

- The catalog follows the shorter introduction. Search filters its cards and the sidebar together, reports result counts, and provides empty-state recovery.
- Native category disclosures keep all nine categories within reach. The homepage has one search field; detail pages keep sidebar search.
- The guide and developer kit follow the catalog. All 20 starter links and the exact installation prompt remain available; long reference content uses native disclosures.
- Shared cards, typography, borders, touch targets, dark-mode labels, code reading, and copy feedback are refined.
- Repeated card and tag blur, observer-gated visibility, and variable card height estimates are removed. Content stays visible and category anchors retain their position.
- Language and theme controls tolerate unavailable storage. Hidden raw text no longer duplicates an entire article in the accessibility tree.

## Measured results

The same production homepage and desktop width were used before and after.
Gzip figures are local compression estimates, not measured network transfer.

| Measurement | Before | After |
| --- | ---: | ---: |
| Homepage HTML bytes, including inline scripts | 565,891 | 481,850 |
| Homepage HTML gzip bytes | 93,027 | 85,290 |
| Shared CSS bytes | 48,113 | 50,934 |
| Shared CSS gzip bytes | 8,734 | 9,347 |
| HTML + CSS gzip bytes | 101,761 | 94,637 |
| DOM elements | 4,457 | 4,059 |
| Full catalog/starter cards | 127 | 107 |
| Elements with computed backdrop blur | 639 | 1 |
| Catalog top at desktop, pixels from page top | 3,756 | 424 |

HTML is 14.9% smaller; the combined HTML/CSS gzip estimate is 7.0% smaller.
The sole remaining backdrop blur belongs to the sticky header. CSS grew to
support the new search, navigation, and accessible states.

No field Core Web Vitals, throttled network timings, or physical mobile-device
performance was measured. These results establish less markup and fewer blur
effects, not a particular load-time improvement.
